# Agent Note: 带类型的后端拒绝原因

Status: implemented

[English](2026-10-09-backend-refusal-codes.md) | 中文

## 问题

维护功能的使用方需要识别不受支持的适配器，而不能解析诊断文本，也不能假定部署清单完整无缺。

## 决策

`LlmRuntime.backendCoverage()` 为每个尚未完成收敛的参与者输出与提供方无关的带类型拒绝码，同时保留诊断原因和准确的提供方注册信息。所有实际存在或保留的适配器实例都参与检查。汇总判断取决于拒绝码，而非诊断文本。

## 考虑过的替代方案

提供方白名单会静默遗漏新增或已撤回的注册项。根据空闲的 agent（智能体）或已停止的调用方推断收敛状态，会混淆前端静止与后端完成。这两种方案均不采用。

## 影响

缺少权威 backendStatus 证据的适配器会阻止排空，即使它从未被使用。受支持子集的测试只能证明该子集；完整配置的集成测试必须保留不受支持的适配器，并明确指出其名称。清单只是证据，不是跳过参与者的许可。单元测试覆盖新增及已撤回的不受支持路由；构建后配置的测试通过经过身份验证的 HTTP 接口检查具名拒绝结果。
