# Agent Note: 网关范围的 DSH 请求身份

Status: implemented

[English](2026-08-25-dsh-gateway-request-identity.md) | 中文

## 问题

OpenAI 兼容网关可以通过静态 `User-Agent` 识别 DeepSeek Harness，但无法把 LLM 调用与发起调用的 DSH 会话或已配置的提供方路由关联。因此，机器绑定凭据会把无关的 DSH 流量归入同一个调用方分组，而直连提供方的 DSH 流量只在会话日志中可见。

## 决定

当已解析 profile 的 `baseURL` 路径以 `/api/llm` 开头，且请求携带 `GenerateOptions.sessionId` 时，`dsh-llm-pi-ai` 会发送 `X-DSH-Session-ID` 和 `X-DSH-Provider`。适配器从当前请求派生这两个值，Harness 拥有的值会取代 profile 中不区分大小写的同名标头。

该身份仅限网关。即使请求携带会话 id，直连提供方端点也不会收到任何一个标头。这样既保留了提供方中立的静态归因规则，又为私有网关提供了审计 DSH 流量所需的不透明身份。DSH 会话日志仍是绕过网关的调用的权威记录。

## 验证

pi-ai 适配器的 mock server 测试会把一个会话发送到 `/api/llm` 基础路径，并把另一个会话发送到直连路径。测试会断言精确的网关标头、冲突值取代以及直连请求不带这些标头。

## 考虑过的替代方案

**向每个提供方发送这些标头。** 已否决，因为直连提供方不需要本地会话关联，而且可能会保留未知的每会话字段。

**在 JSON 请求体中放置身份字段。** 已否决，因为提供方请求 schema 可能拒绝未知字段，而 HTTP 标头可以穿过 OpenAI 兼容网关实现，且不会成为模型输入。

**使用机器凭据作为身份。** 已否决，因为一个凭据会服务多个 DSH 会话和提供方路由，无法支持每会话归因。

## 后果

网关可以把流式和非流式调用关联到 DSH 会话记录，无需查看 prompt 或本地路径。挂载在 `/api/llm` 之外的网关不会收到动态身份，直到其路由命名获得明确决定；这种狭窄检测避免了通过端点类比泄露会话 id。
