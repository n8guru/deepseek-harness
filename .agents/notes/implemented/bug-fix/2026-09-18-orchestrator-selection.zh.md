# Agent Note：编排会话选择持久化

Status: implemented

[English](2026-09-18-orchestrator-selection.md) | 中文

## 问题

原生会话选择器在 DSH 源中全局保存上次选择。在另一个框架中查看工作会话会改变该恢复目标，但不应在重新加载后改变 Forage 编排器选定的会话。

## 决策

[选择桥接](../../../../apps/web/src/orchestrator-bridge.ts)仅在嵌入窗口明确选择允许列表中的 Forage 父源时观察原生会话列表。它向该精确父源发送选定且列于 Host 列表中的会话标识符；仅存在于子代理目录的选择会清除候选项，因为这些会话需要父级地址。父页面持有独立的固定选择，验证发送框架和源，并要求用户明确点击 Use this session 后才通过现有会话嵌入路由恢复该标识符。全局恢复的工作会话仅是候选项，不会隐式替换已固定的选择。应用上下文负责释放订阅。

## 考虑过的替代方案

**从 Forage 读取 DSH 存储。** 跨源访问被禁止，而且全局值不能标识编排器。

**隐式创建专用会话。** 这会改变用户的选择，并可能创建不需要的会话。选择和创建仍由原生选择器负责。

## 影响

回执仅包含会话标识符，不包含对话文本、凭据、页面上下文或提示权限。普通顶层 DSH 和不受信任的父源不会收到回执。浏览器禁用存储时只能保留已挂载框架中的选择。聚焦单元测试覆盖源限制、选择变化和释放；组合浏览器冒烟测试覆盖原生选择及查看工作会话后的重新加载。不改变代理对话或模型输入。
