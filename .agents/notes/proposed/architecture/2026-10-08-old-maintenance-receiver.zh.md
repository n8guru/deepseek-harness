# Agent Note: 不虚构认证的旧源码持久维护接收器

Status: proposed

[English](2026-10-08-old-maintenance-receiver.md) | 中文

## Problem

内存中的准入截止状态无法跨进程替换保留。调用者提供的 owner 字符串或成功的浏览器信任检查不能证明维护权限已被认证。销毁宽限期限也不能证明生产者已完成退出。

## Proposal

保留旧源码候选中的精确初始准入能力及实际失败发布、WorkerRun 退出证据。可选维护接收器通过现有会话持久化后端记录完整修订，拒绝畸形状态转换，对排队命令和返回值做快照，保留已退役的 owner/run 标识，并在销毁时等待进行中的写入。Close 先于持久化生效；持久性不确定时，运行中的 Host 保持关闭。Release 从不重新打开当前进程。

在找到经过认证的传输主体之前，源码候选刻意不绑定 HTTP。现有 Connection 的 Host/Origin 检查明确不包含认证。接收器未在默认 bundle 中启用。

## Alternatives considered

将 loopback、Host、Origin、消息体 owner 或服务存在性视为认证，会虚构权限。增加另一套凭据存储或服务器会引入未经请求的安全机制。直接调用服务的证据仍可证明持久化和所有权行为，但不能称为经过认证或运行中首次截止的证明。

## Acceptance criteria

完整接收器需要通过现有已认证网关的真实调用，以及未认证和主体替换的拒绝测试。完整启动隔离需要在所有生产者能够发布前强制排序，不能仅靠接收器构造后暂停准入。仍需独立评审。

隔离 Loader 脚本使用重新构建的旧产物且不调用付费提供者：finish 脚本覆盖初始物化与退出计数；receiver 脚本通过三个新进程测试持久关闭与释放。直接服务调用不满足传输验收要求。

## Risks

构造时的重放暂停无法保护接收器构造前的时间段。完整 Host 编译还存在无关的 markdown 项目 TS6307 错误；受影响包的编译与打包只是更窄的结果。这些产物不会关闭已经加载的生产 Host、修改凭据、激活版本或授权重启。
