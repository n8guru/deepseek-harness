# Agent Note: 操作者活动诊断传输检查点

[English](2026-10-09-operator-activity-transport-checkpoint.md) | 中文

Status: proposed

## Problem

已审阅的 operator-activity/v1 规范要求通过 socket 认证的活动、权威原生暂停状态、持久化受约束回执，以及最终模型入口处的检查。仅将传输作为释放权限，会让不完整的控制状态唤醒 conductor。

## Proposal

此源代码检查点通过 Connection 实现现有 Gateway 活动流和显式授权的生产者读取。socket 与浏览器认证生命周期、精确 Agent 身份、严格帧校验、单调时钟年龄和心跳新鲜度共同产生诊断活动。它不引入轮询器或运行时安装。

快照始终报告 `eligible: false`。原生 Stop 和 goal 所有者提供控制状态。具有显式读取和受约束准入授权的生产者，在精确元组、新鲜度及原生暂停状态检查通过后，可以获得保持暂停的持久化托管。Connection 在等待刷新完成后重新检查授权、实时所有者和活动。受约束准入既不唤醒输入，也不授权模型入口；最终认领和请求前检查仍是独立工作。现有不受活动约束的生产者保持原有行为。原始认证 WebSocket 测试不证明可信 GUI DOM 输入。

## Custody persistence

原生暂存在普通收件箱插入前，通过读取时必需的事件记录完整有序回执选择及原始活动与控制元组。仅使用可选 splice 标记并不安全：旧读取器可能忽略它并运行暂停输入。必需事件让不兼容读取器拒绝日志；带标记的 splice 也拒绝缺少托管记录的状态。将消息保留在该事件中，使重启能够重建中断的插入，而无需第二个队列。投影缓存使用新的状态版本。

暂存结果仅是在内存中的证据；托管确认要求参与持久化的 Session 刷新成功。仅精确重试已有回执时，可在暂停状态下返回原身份；混合重试必须在新增变更前获得当前未暂停元组。托管、重复回执和终止回执均不证明投递。记录的 epoch 仅具历史意义，所有受约束消息仍保持暂停。准入与刷新后校验不完成最终模型入口检查或组装资格验证。继承的规范持久化历史兼容性问题仍是明确的资格验证义务；此次准入变更不改变持久化类型。

## Alternatives considered

独立待处理队列会重复原生收件箱的职责。没有必需事件的可选 splice 元数据，会让旧读取器静默丢弃暂停状态。两者都未采用。

## Acceptance criteria

完整要求仍见已审阅规范 `2026-10-09-operator-activity-snapshot.md`。此检查点不满足 step70。聚焦传输测试和编译记录在 `.agents/evidence/conductor-activity-checkpoint.txt`，其中还包含四项后续步骤提案。验收前仍需独立审阅和组装 GUI/profile 资格验证。现有安装所有者保留独占激活权限。

## Risks

托管元数据不授权释放：在完整原生准入及最终模型入口校验存在之前，暂存路径刻意保持每条受约束回执的暂停状态。诊断快照和原始 socket 测试不能建立这些保证。不支持 v1 的旧运行时仍不受支持；不暗示活动推断回退或反向移植。
