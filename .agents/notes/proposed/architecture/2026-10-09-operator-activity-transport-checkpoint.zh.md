# Agent Note: 操作者活动托管与最终入口

Status: proposed

[English](2026-10-09-operator-activity-transport-checkpoint.md) | 中文

## Problem

已审阅的 operator-activity/v1 规范要求通过 socket 认证的活动、权威原生暂停状态、持久化受约束回执及最终模型入口检查。生产者快照不能在 Stop、Focus、目标、维护、前台或传输状态变化后继续作为释放权限。

## Proposal

Connection 向原生驱动器提供已认证观测和当前控制修订值。诊断快照报告当前资格，但不唤醒输入。新准入、合格交互或已认证的解除暂停动作可以请求原生释放；读取、Pong、重连和精确回执重试均不能。不引入轮询器、第二个队列或运行时安装。套接字读取器不会等待原生拥有的释放刷新：同一套接字后续的离开或 Stop 帧必须在刷新完成前使正在进行的选择失效。

现有原生维护预留在刷新托管前选择最多十个有序标识。驱动器在刷新后、认领观察者与异步准备之后、用户输入接纳之前以及最终适配器分发处，重新检查实时资格与修订值。跨等待发生日志变化时，保守地推迟该选择。内部同步日志写入不会使其自身的控制检查失效。现有精确请求标记通过流中间件携带进程本地最终回调；记录的元组不能恢复它。步骤前中间件必须保留受约束消息对象及其精确顺序：删除、拒绝、重排、重复、替换或注入都会推迟托管，而不是将其终结。

## Custody persistence

读取时必需的托管事件在普通收件箱插入之前保留完整有序回执。它让重启无需第二个队列即可重建中断的插入，并让不兼容读取器拒绝执行。暂存本身不是持久托管；确认前必须成功完成有持久化参与者的 Session 刷新。精确重试返回相同的有序标识，不变更或唤醒；载荷冲突和不具资格的混合批次拒绝新增插入。

现有 user/message 提交仍是原生接纳，不证明模型或用户已看到输入。接纳前延期会将回执按原顺序恢复到迟到项之前，并且不取消并发前台输入。原生接纳之后的暂停仍可阻止适配器分发，但不能撤回或重复已接纳历史。此路径不发出已投递 ACK：eligible 仅为当前诊断，held 也涵盖释放尝试后观测到的暂停。前台输入插入会使选择失效，即使随后再次移除该输入；前台认领不能吸收受约束输入。维护结束时若未启动驱动器，则撤销已武装的选择。空的工具继续步骤不会被误判为尚未接纳的托管。驱动器结束时撤销进程本地选择；重启后保持暂停且 Stop 为 unknown，直到操作者显式恢复并出现新活动。

不修改持久化类型或已接纳历史。继承的规范持久化历史兼容性问题仍是明确的资格验证义务。

## Alternatives considered

持久化释放权限会在重启后恢复过期活动。将快照视为不可撤销能力会漏掉刷新后和准备阶段的竞态。第二个收件箱会重复原生托管与幂等职责。因此实现复用现有回执、认领和 user/message 标识，仅增加可撤销的实时选择。

## Acceptance criteria

完整要求仍见已审阅规范 `2026-10-09-operator-activity-snapshot.md`。确定性 HTTP/WS 与原生测试覆盖正向入口、暂停竞态、有序重试、有界选择和新进程接纳。这些生产方检查不等于独立验证、完整 GUI/profile 资格验证或 step70 验收。现有安装所有者保留独占激活权限。

## Risks

原始认证 socket 测试不证明可信 GUI DOM 输入。原生接纳可能先于中间件失败或后续暂停，因此绝不能把托管和已接纳历史标为实际投递。持久化 Stop 与历史资格验证以及完整组装审阅仍是独立义务。不支持 v1 的旧运行时仍不受支持；不暗示活动推断回退或反向移植。
